# 演示与验收指南

本文对应 `docs/01` 的验收标准，给出一条 5 分钟的演示路径。演示密码统一为 `admin123`。

## 1. 启动

```powershell
pip install -r requirements.txt
python run.py
```

打开 <http://127.0.0.1:8000/>。如果之前运行过演示，删除 `.data/store.json` 后重启即可恢复种子数据。

## 2. 角色与菜单

| 账号 | 角色 | 应看到的菜单 |
|---|---|---|
| `admin` | 管理员 | 全部菜单，含用户与权限、审计日志 |
| `operator` | 运营 | 总览、Agent、设备、订单、工单、审批、报表、社区、事件 |
| `repairer` | 维修 | 总览、Agent、设备、工单、事件 |
| `finance` | 财务 | 总览、Agent、设备、订单、审批、报表 |
| `user` | 居民 | 总览、Agent、设备、我的订单、我的报修、我的申请 |

验收点：用 `user` 登录后直接访问 `#/users` 或 `#/reports` 会被前端送回可见首页；直接请求 `/api/users` 会返回 `403 FORBIDDEN`，并写入 `permission_denied` 审计日志。

## 3. 预约与订单

1. 使用 `user` 登录，进入「充电设备」。
2. 选择 A 区-01，点击「预约」，设置一个未来 2 小时的时间段，提交。
3. 在「订单管理」看到订单状态为「已预约」；点击「开始充电」，再点击「完成结算」，输入电量，订单变为「已完成」。
4. 用 `admin` 为同一枪口、同一时段再创建预约，接口返回 `409 RESERVATION_CONFLICT`。
5. 普通用户只能看到自己的订单；`admin` 能看到全部授权社区订单。

## 4. 设备事件与工单

1. 使用 `operator` 登录，进入「设备事件」→「接入事件」。
2. 选择 A 区-01，事件类型 `fault`，Payload 填 `{"code":"E-107","temperature":72}`，提交。
3. 设备状态变为故障，自动生成 P1 工单；再用新的 `event_id` 提交同一设备故障，会升级原工单而不是新建。
4. 使用同一个 `event_id` 重复提交，返回 `duplicate: true`，不会重复处理。

## 5. 工单验收关闭

1. 使用 `repairer` 登录，进入「维修工单」，打开处于「待验收」的 **T004**。
2. 直接点击「验收关闭」会被拒绝，提示缺少测试订单 / 心跳。
3. 点击「心跳」模拟设备心跳，再点击「测试订单」并确认，创建一笔 0 元测试订单。
4. 重新打开 T004，验收检查全部通过后点击「验收关闭」，工单变为已关闭，设备回到可用状态。
5. 关闭动作要求：心跳 ≤ 10 分钟、测试订单已完成、维修回填非空；三者缺一不可。

## 6. 高风险 Agent → 审批

1. 使用 `operator` 或 `admin` 登录，进入「Agent 工作台」。
2. 输入：`为订单 O2005 申请退款 9.6 元`。
3. Agent 返回「高风险 / 待审批」，创建审批编号（如 AP1005），并明确尚未执行任何资金变更；订单状态保持已完成。
4. 使用 `finance` 登录，进入「审批中心」，打开申请，填写审批意见并通过；状态变为「已执行」，订单变为「已退款」。
5. 再次点击审批通过会返回 `409 APPROVAL_ALREADY_DECIDED`。
6. 使用 `operator` 输入 `暂停 P003 停机检修 8 小时`，同样只生成停机审批；用 `user` 输入同样内容会被直接拦截（无停机权限）。

## 7. 报表与审计

1. 使用 `finance` 或 `admin` 进入「运营报表」，切换近 7 天 / 30 天，导出 CSV。
2. 报表只统计已完成订单并扣除退款；测试订单不计入收入。
3. 进入「审计日志」，可以看到登录、预约、设备事件、工单、审批、报表导出和权限拒绝记录；每条记录带 `trace_id`，可复制关联。
4. `/api/health` 的 `checks.storage` 显示 JSON 存储状态；模拟磁盘写入失败时，写接口返回 `503 STORE_UNAVAILABLE` 并记录结构化错误日志。

## 8. 常用 API 验证

```powershell
$login = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/auth/login `
  -ContentType application/json -Body '{"username":"admin","password":"admin123"}'
$headers = @{ Authorization = "Bearer $($login.access_token)" }
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/dashboard -Headers $headers
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/reports/operations?days=7 -Headers $headers
```

## 9. Netlify 预览

Netlify 仅提供 JavaScript/TypeScript 与 Go 运行时，不能直接运行 FastAPI。仓库采用：

- **本地 / Docker**：FastAPI 真实后端；
- **Netlify**：同一套静态前端 + `netlify/functions/api/api.mjs` 内存适配器，使用相同种子数据和 API 契约，便于一键预览。

Netlify 预览为演示实例，函数冷启动或实例回收后数据会回到种子；生产环境请使用 FastAPI + 共享数据库部署。
